# Notes for agents working on Appears

Appears is a Mac menu bar app that notices what you're working on and shows related things you already have, without a query. This repo also holds its site, [appea.rs](https://appea.rs). Read [README.md](README.md) for how it works, building and testing, and [CONTRIBUTING.md](CONTRIBUTING.md) for the checks a change needs.

Don't push, deploy, tag, publish a release or commit unless the person you're working for asks. Releases and deploys are the maintainer's job.

## Rules that protect the product's promise

Appears reads your screen. People trust it only because these hold, so treat them as hard constraints, not preferences.

- **The engine never gets the network.** `mac/project.yml` gives `AppearsEngine` the App Sandbox with no `com.apple.security.network.client` or `network.server`. Never add them.
- **Networking lives in exactly two places:** `AppearsDownloads`, linked only into `AppearsDownloader.xpc` for the two model downloads, and Sparkle's sandboxed Downloader XPC service for app updates. `mac/scripts/build-sparkle.sh` strips Sparkle's in-process downloader and web views; keep `check-no-network.sh` checking the framework too.
- **The app has no networking code.** It can't be sandboxed, because Accessibility isn't allowed in the App Sandbox, and it can't sandbox itself: any self-applied `sandbox_init` profile makes macOS refuse it Accessibility. So `mac/scripts/check-no-network.sh` is the guard. Run it on every build you hand over and keep it passing. Don't link Network.framework, URLSession or sockets into the app or `AppearsContext`.
- **No analytics, telemetry or crash reporting**, anywhere in `mac/` or on the site.
- **Nothing about the screen is stored.** Context text lives in memory only, and calendar events count as context. The journal keeps item ids, scores, outcomes and a salted fingerprint. The one exception is `debugContext`, behind a Debug-build-only setting, kept for 14 days. Never log context text, not even with `NSLog`.
- **Silence is the default.** No sounds or system notifications. Ambient suggestions use the chosen alert style: menu bar motion by default, a still dot, or an explicitly enabled in-memory toast. Every style stays behind the same lookup timing and `SurfacePolicy` (the answer model's probability that a result is what's needed, a one-minute signal gap, and deduplication within a document or conversation). Without the answer model nothing signals. Toasts never activate the app or persist content in Notification Center. Ignoring or dismissing a result never adds global backoff; dismissing suppresses that item in its context. Don't loosen the timing or policy without checking `appears eval`'s false-surface rate.
- **Exclusions stay on:** password managers and secure fields (`Exclusions.swift`), private browser windows, and Safari in ambient mode unless the setting allows it.
- **The model download stays restricted.** `AppearsDownloader.xpc` is sandboxed with network.client only and no user-file access. Its XPC interface takes no screen text, file paths or URLs. The signed `model-download.json` (the embedder) and `decider-download.json` (the answer model, fetched after the embedder) pin every URL, size and SHA-256, and the engine reads only a verified, completely installed model. Onboarding never waits for either download.
- **No real data** in the repo, tests, screenshots, issues or the site. Use `demo/` (generated by `demo/make-demo.py`; phone numbers are 555-01xx, emails use `.example`).

## Layout

- **`mac/Packages/AppearsKit`:** builds and tests with the Command Line Tools. Run `swift test` with `DEVELOPER_DIR` set to Xcode to avoid a Testing-macro plugin error with the CLT toolchain.
  - `AppearsCore`:
    - `Sources` (`FileScanner`, skip rules), `Extractors`, `NotesReader` (gzipped protobuf), `MessagesReader` (`chat.db` and local photos, read-only);
    - `IndexStore` (GRDB, FTS5, float16 vectors), `VectorIndex` (brute force), `Indexer`;
    - `QueryBuilder`, `Recall` (retrieval, passages and the decision), `DecisionFraming` and `Decider` (how a lookup is put to the answer model), `Journal`, `SurfacePolicy`;
    - `Engine` (the engine's logic and XPC protocol, also used in-process by the CLI);
    - `CalendarEvent` (an upcoming meeting as a context, with conferencing boilerplate stripped) and `CalendarSchedule` (when to look).
  - `AppearsContext`: `ContextReader` (Accessibility), `Browsers`, `Exclusions`, `ScreenText` (OCR fallback).
  - `AppearsMessages`: the read-only Messages database reader, dates, attributed-body decoding and conversation links.
  - `AppearsMCP`: `appears mcp`, an MCP server over stdio (`MCPServer`, `Tools`), and `AgentIndex`, which opens an index read-only. It never journals, and its stderr log never gets query text, results or file content.
- **`mac/Packages/AppearsModel`:** needs Xcode, since MLX compiles Metal shaders.
  - `EmbeddingGemma2`: vendored from [EmbeddingGemma2Swift](mac/Packages/AppearsModel/ThirdParty/EmbeddingGemma2Swift). Keep its notices in `ThirdParty/`.
  - `GemmaEmbedder`: loads the vision tower lazily and unloads it after indexing.
  - `Lightning`: the answer model, H2O-Lightning-4B (Qwen3.5-4B, MLX 4-bit, text only), as AppearsCore's `Decider`. A port of mlx-vlm's Qwen3.5 with mlx-lm's gated delta kernel (keep their notices in `ThirdParty/Lightning`); it loads on first use and unloads when idle. `LightningTests` pin its tokens and probabilities to `mac/scripts/reference_decisions.py`.
  - `AppearsCLI`: the `appears` command.
- **`mac/Engine/main.swift`:** the XPC service. It loads the embedder once, picks up the answer model when its download is verified, and keeps a separate index for `-demo`.
- **`mac/Downloader`:** the model downloader: the embedder, then the answer model.
- **`mac/App`:** `AppModel` (the context loop, asking, ambient, meetings, feedback), `CalendarWatcher` (EventKit, one timer for the next meeting), `StatusController` (the menu bar item and the non-activating panel), `PanelView`, `SettingsView`, `OnboardingView`, `Glyph`.
- **`web/`:** appea.rs. See [Site conventions](#site-conventions).

## Design

The look is shadcn/ui's: the zinc scale, hairline borders, 8 px card and 6 px control radii, a black primary, muted secondary text, a ⌘K-style results list, and one blue accent (`#2563EB`) used sparingly. [brand/README.md](brand/README.md) has the tokens and the logo geometry.

- **Code:** `Theme.swift` holds the app's tokens, button styles, `Kbd`, `Badge` and `Mark`; the site uses the same values in `web/src/styles`.
- **Type:** the system font in the app, Inter on the site. No serif type, no warm paper tones, no Geist, no Liquid Glass capsules.
- **The panel** hangs from the menu bar ring and never activates the app, so focus stays where it was.
  - **Header:** one line: "Related", then the front app's icon and the window's title, muted. For a meeting, a calendar glyph and "2:00 PM · title". No count badge.
  - **Rows:** up to ten in a scrolling list with about five visible, and no hidden "less likely" list. The header and footer stay fixed, and arrow keys keep the selection in view. Each row has a thumbnail, a name, and a source excerpt with matching terms emphasized, or a specific name match. A small Orbit outline beside the name fills to the 0–1 confidence score; hover or VoiceOver gives the exact value. When and where are muted below.
  - **Evidence:** every row shows why it matched. The selected row gets the muted background and, when available, the quoted line that answers. Pictures show OCR only when a clean phrase matches the context; otherwise the thumbnail and any specific name match are the evidence. Never invent an explanation for an image's similarity.
  - **Footer:** at most three keys on one line (↩ open, ␣ preview or ⌥⌘C copy, ⌫ hide at the far end), and gone when there's no list.
- **Logo:** "Orbit", an open ring with a detached dot in its upper-right gap. `Orbit.swift` holds the app's geometry and `web/src/lib/orbit.ts` the site's. The five menu bar states are monochrome: idle, indexing (shorter arc), found (dot), paused (pause bars) and needs setup (exclamation mark).
- **Name:** "Appears", capitalized, in sentences. The wordmark is lowercase "appears" in a bold weight beside the mark. The domain is appea.rs.

## Embedding prompts

EmbeddingGemma 2 expects:

- Queries: `task: search result | query: …`.
- Documents: `title: … | text: …`.
- Images: no prefix.

`EmbeddingGemmaPrompt` in `Embedder.swift` is the only place these strings live. Changing the embedder's `modelID` makes every index re-embed from scratch.

## The answer model

Retrieval finds candidates; H2O-Lightning-4B decides. It reads a record (where the person is, and for a meeting or a window the details), a question (the draft or selection itself when there is one) and up to 15 candidates plus "none", and returns a probability for each. That probability is each result's order and ring; one minus "none" is what an ambient signal needs.

- **The prompt is the model's contract.** `DecisionPrompt` in `Decider.swift` reproduces H2O's shim (v1.2.3, `serve_config.json`) exactly: the chat template, `record:`/`question:`/`options:`, the letters, `Answer:` and temperature 0.75. Don't edit those strings; `LightningTests` will fail if you do.
- **Change what it reads in `DecisionFraming`**, never by adding score multipliers. It needs to see what a person would: the open conversation marked, the text around a short document passage, a picture's recognized text.
- **No hand-set confidence.** Don't reintroduce boosts, fitted weights or z-scores to rescue a case: show the decision model better candidates or better text, or add the case to the eval.
- **Updating the weights:** `mac/scripts/fetch-decider.sh` pins the source revision and the converter versions; then update `decider-download.json`, rerun `reference_decisions.py` and the eval, and upload with `mac/scripts/upload-model.py --decider`.

## Ranking changes

Run `appears eval --verbose` before and after any change to `Recall`, `QueryBuilder`, `DecisionFraming` or the answer model, and put the numbers in the PR and commit message. Add a scenario to `demo/scenarios.json` (and files to `make-demo.py`) for each failure you fix. Add negative scenarios, where silence is the right answer, as often as positive ones. Nothing is fitted to these scenarios, but the framing and the 0.8 threshold were checked against them, so treat the eval as a regression check, not a benchmark.

## Site conventions

appea.rs is one static Astro page behind a small hand-written Worker (`web/src/worker.ts`). [web/README.md](web/README.md) says what's where.

- **One source for copy.** `web/src/site.ts` holds all of it; the page, its Markdown version, `llms.txt` and the share card read from there. Keep the README, the site and the app's onboarding saying the same things.
- **Markdown for agents.** `/index.md` is built beside the page and also served at `/` when the request's Accept header prefers `text/markdown` (`prefersMarkdown()` in `web/src/lib/negotiate.ts`; ties go to Markdown). It carries the same facts and links as the page, with absolute URLs, and drops chrome. Choose by the Accept header, never by user agent.
- **`llms.txt`** follows llmstxt.org and is served as `text/plain; charset=utf-8` (set in `public/_headers`).
- **The Worker** only sees the paths in `assets.run_worker_first`. Never route asset folders through it. For page paths it fetches the static file with the original request, so redirects, ranges and conditional requests keep working.
- **No FAQ markup, keyword stuffing or "AI summary" blocks,** and no analytics or third-party scripts.
- **Sitemaps** list pages only, not `.md` files or `llms.txt`.
